A graph, a YAML file, and one artifact

Introduction · the boundary

A compiler, not an agent runtime

This is the single most important thing to understand about the tool. Ladder Graph produces instructions and inert data. Execution is always someone else's job: your harness, your host application, you.

What it does

  • Authors workflows visually and in canonical LGIR YAML
  • Validates topology, contracts, loop and group ownership
  • Computes a deterministic topological order and a source hash
  • Reports per-target capability as native, instructional, or unsupported
  • Compiles one artifact you can copy or download
  • Saves projects and revisions locally in your browser

What it never does

  • Call a model, agent, tool, MCP server, or connector
  • Execute shell, Python, or JavaScript — imported YAML is data, never code
  • Store provider credentials or create an account
  • Upload, fetch, or inspect the media your input contracts describe
  • Install skills, grant permissions, or edit harness configuration
  • Send telemetry, sync to a cloud, or claim an instructional feature is enforced

Value

Why design the workflow before you run it

Multi-agent prompts fail structurally more often than they fail semantically: a loop with no bound, a join that never releases, a branch nothing merges. Those are graph properties. You can see them, and a compiler can prove them, before a single token is spent.

Correctness

Structural bugs surface at authoring time

Unbounded loops, back-edges, arbitrary cycles, duplicate IDs, missing endpoints, and edges crossing an execution-group boundary are errors with a stable code, an exact source path, and a safe repair you can apply in one click.

Portability

One design, five destinations

The same validated graph compiles to Codex, Claude, Hermes Agent, Python, or TypeScript. Compilation is deterministic: the same source hash yields the same artifact, so diffs are reviewable and fixtures are stable.

Legibility

The graph is the documentation

A reviewer reads execution order, dependencies, approvals, and cost gates from the topology instead of reverse-engineering a wall of prose. Capability reporting names every skill, connector, and permission the artifact will require.

Trust

Nothing leaves the browser

No account, no credentials, no telemetry, no cloud sync. The PWA precaches its shell, fonts, templates, schema, worker, and WebAssembly, so the whole tool keeps working with the network off.

Value · what you get out

Five targets, one file each

Pick the target in the header before you compile — the studio adjusts its suggested skill and connector catalog to match, and the capability report tells you what that target supports natively, what it can only express as an instruction, and what it cannot express at all. Unsupported constructs are never dropped silently.

Codex

Markdown with Agent Skills-compatible frontmatter. Saves under .agents/skills/; repo-wide instructions stay in AGENTS.md.

Claude

Equivalent SKILL.md content, saved under .claude/skills/.

Hermes Agent

Python

Three edge kinds

How nodes connect

Dependency orders work. Data carries a typed payload between contracts. Control routes a branch. A join only waits and releases; it does not combine — that is an aggregator's job.

Four visual macros

Shapes you insert whole

Parallel, Pipeline, Reduce, and Verify materialize canonical nodes and edges into the YAML before validation — so saved files stay portable, with no hidden expansion format.

Seven transforms

Data moves without code

select, rename, merge, filter, deduplicate, sort, slice. Declarative only — arbitrary code transforms are deliberately out of scope.

How to use · the path

Template to artifact in ten minutes

Start from a starter workflow rather than a blank canvas. There are multiple outcome-led templates across subject areas and editable role/agent templates with platform specific tools/skills behind them.

01Open a template

Pick an area on the welcome screen — core patterns, research, security, multimodal, writing, and more — then open a workflow in the studio.

02Edit a role

Select a node. In the inspector, adjust its role, prompt, output schema, and its skills, tools, connectors, and permissions.

03Read the YAML

Switch to split or YAML mode. Every canvas action you just took is visible as a patch to the canonical document.

04Find the diagnostic

The header shows valid, errors, and warnings. Open the drawer to read the finding — the next slide walks through one.

05Apply the safe repair

Where a repair exists, applying it edits the YAML for you. Errors block compilation; warnings do not.

06Choose a target

Codex, Claude, Hermes Agent, Python, or TypeScript. The suggested capability catalog changes with your choice.

07Compile

The bottom drawer returns one artifact plus its filename, MIME type, source hash, compiler and adapter versions, and a capability report.

08Copy or download

Save the Markdown into your harness's skills directory, or import the module into your host application.

How to use · worked example

An unbounded loop, and its safe repair

This is the canonical diagnostic — the one the ten-minute validation study is built around. A revision cycle that can spin forever is the most expensive structural bug in an agent workflow, and it is the easiest one to catch on a graph.

Error LGIR-LOOP-UNBOUNDED
Source pathspec.nodes[4].config
Noderevise-loop · kind loop
ExplanationThe loop declares a body but no iteration ceiling and no exit condition. A back-edge from critique to draft was also found; back-edges and self-edges are invalid because a loop owns its body explicitly.
CapabilityInstructional on Codex, Claude, and Hermes Agent — the bound is rendered as an explicit instruction, not mechanically enforced.
Safe repairRemove the back-edge, list the body members on the loop, set maxIterations between 1 and 100, add an exitCondition, and declare an onExhausted policy.
Valid 0 errors · compilation unblocked

Before · rejected

- id: revise-loop
  kind: loop
  name: Revision
  config:
    body: [draft, critique]
# and, in spec.edges:
- from: critique
  to: draft          # back-edge

After · safe repair applied

- id: revise-loop
  kind: loop
  name: Bounded revision
  config:
    body: [draft, critique]
    exitCondition: evaluation.passed == true
    maxIterations: 3
    onExhausted: stop
Read the capability line, not just the severity. "Instructional" means the compiled artifact states the bound in words to a model that may ignore it. If a limit must be enforced, enforce it in the host application that binds the handlers.

Architecture

Three deliberately narrow layers

Each layer owns one thing and does not reach into the next. That is what keeps the compiler deterministic while the UI stays responsive.

React studio React 19 · Vite · Tailwind 4 · React Flow · CodeMirror 6 · Zustand · Dagre

Owns interaction, YAML CST patching, layout, browser files, copy and download, and local persistence. It never decides what is valid.
Dedicated Web Worker analyze · format · compile · migrate

Owns the asynchronous compiler protocol and keeps parsing and compilation off the UI thread, so a 200-node graph stays interactive.
Rust WebAssembly core the semantic authority

Owns LGIR semantics, diagnostics, hashing, normalization, migration, and deterministic target generation. Rust structs — not the JSON Schema — decide what a valid workflow is.
Two safety nets. If WebAssembly cannot initialize, the worker falls back to a TypeScript parity compiler so projects stay recoverable. And when YAML syntax is invalid, source editing and autosave continue while the canvas goes read-only — lastValidYaml preserves a recoverable graph.

Architecture · state

Where your work lives

All of it is in your browser. None of it is a backup.

IndexedDB

Project metadata, the active YAML, lastValidYaml, targets, template indexes, and revision indexes.

OPFS

Revision bodies prefer the Origin Private File System and fall back to IndexedDB when it is unavailable.

Autosave and revisions

Valid and invalid revisions are kept distinct and pruned to the most recent 30 per project, so a broken edit never erases a good one.

Persistent storage is asked for, never assumed

The app requests persistent browser storage only after an explicit action from you, and exposes quota and persistence state in the storage dialog.

Deployment and offline

vite-plugin-pwa precaches the shell, schema, self-hosted fonts, worker, and WebAssembly. Vercel serves a static dist directory with CSP and security headers — no server, no runtime CDN.

Export what matters. Browser storage is convenient local state, not a durable backup. Clearing site data clears your projects. Use Export YAML for anything you would be unhappy to lose.

Security & privacy

Imported YAML is data, never code

The threat model is simple: you may open a workflow file someone else wrote. Everything below follows from making that safe.

Import limits

What gets rejected at the door

Documents over 2 MB or 1,000 nodes. Custom YAML tags, anchors, aliases, and external references. Duplicate IDs, missing endpoints, unsupported node kinds, and arbitrary cycles.

Rendering

Nothing is ever executed

Imported content is not evaluated. Generated Markdown and source code are rendered as text — never injected as HTML, never run in the browser.

Permissions

Artifacts grant nothing

A compiled artifact names the skills, connectors, and permissions it requires. It does not install, grant, or authorize any of them. Your harness still decides.

Catalog

Suggestions, not inventory

Catalog entries are authoring suggestions. Ladder Graph does not inspect your configuration or check what you have installed. OpenRouter profiles are research snapshots — verify model slugs, endpoints, parameters, availability, and pricing before use, and never put credentials in LGIR.
